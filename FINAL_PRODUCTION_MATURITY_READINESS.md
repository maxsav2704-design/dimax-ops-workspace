readiness percentages, test totals, source SHAs, APK hashes, timestamps, or live
environment results. Those values change as the release candidate changes and are
valid only when generated by the release checks.

## Closed Critical And High-Risk Classes

The release candidate includes automated coverage for these risk classes:

- exact backend dependency constraints and production-image runtime hardening;
- inactive-account rejection, generic login failures, refresh rotation locking,
  and account-bound mobile authentication state;
- tenant and installer access isolation across admin, installer, and sync APIs;
- savepoint-isolated sync event application and recovery evidence;
- fresh-database migrations plus legacy schema upgrade and downgrade checks;
- database-backed readiness separate from process liveness;
- redacted structured HTTP logs and capability-token-safe proxy logging;
- concurrent one-use public file access and single journal signature enforcement;
- fail-closed production image, API URL, and Android signing configuration;
- dependency policy checks for backend, admin, and mobile;
- offline installer cache, queue, conflict, reset, and cold-resync contracts;
- end-to-end business smoke for import, assignment, completion, earnings, and
  project reporting.

A risk class is considered closed for a release candidate only while the relevant
generated gate remains `PASS`. This index is not evidence by itself.

## Production Inputs

Owner-provided values are listed in `PRODUCTION_ENV_REQUIRED_VALUES.md`. Production
requires real values for all of the following:

- PostgreSQL connectivity with TLS;
- public HTTPS API and admin hosts;
- JWT, storage, integration, and bootstrap secrets;
- a digest- or source-SHA-pinned backend image;
- the mobile production API URL;
- an Android release keystore and all required signing variables.

Examples and placeholders must continue to fail production validation. They must
never be counted as deployment readiness.

## Release Invariants

- All four repositories must be clean, reviewed, synchronized with their upstream
  branches, and represented by immutable commit identities.
- Backend migrations, quality gates, admin build/tests, mobile quality gates,
  dependency audit, and business smoke must pass for the same release source.
- Android interaction evidence must be bound to the current release artifact, not
  inherited from an older APK or source revision.
- Production remains `NO-GO` until real environment and signing validation passes.
- Deployment is not complete until `POST_DEPLOY_SMOKE.md` passes against the real
  HTTPS hosts and production infrastructure.

## Decision Rule

Use only the decision in `artifacts/release/release-status-latest.md`. If that
artifact is missing, stale, or reports a blocked gate, this document cannot be used
to claim production readiness.
