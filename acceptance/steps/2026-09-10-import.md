## P1: Numeric import silently truncates door quantities

Before the fix, `int(float(value))` accepted 1.5 as one door. Floating-point
rounding also concealed small fractional parts. The price parser did not
explicitly reject non-finite decimals before preparing rows.

Backend commit `1acf70d6b6538acf1e205668b3ad4cb2a39f59c5`:
- Validate quantities as exact finite Decimal whole numbers in range 1..1000.
- Reject non-finite prices, keeping zero, comma notation and existing defaults.
- Version the import fingerprint so old previews cannot bypass new validation.
- Preserve strict atomic rejection and explicitly authorized partial import.
- Keep public fields, door identity, rates, ledger semantics and history intact.

No migration is needed. Previously truncated imports are not automatically
rewritten: reconcile affected historical source files before altering real doors.
