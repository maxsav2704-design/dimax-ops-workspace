## Confirmed Defects and Changes

1. P1: cancellation omitted the original credit from installer statements but kept
   the debit, producing a negative month instead of zero. The statement now keeps
   dated credit/debit movements; a financial correction still replaces its original
   and balancing reversal with the corrected amount at the original completion date.
2. P1: cancellation searched only active ORIGINAL entries and left a CORRECTION
   accrued. Cancellation now reverses the current ORIGINAL or CORRECTION exactly
   once. The shared active-work predicate also excludes reversed corrections from
   operational reports and detects an existing corrected accrual before completion.
3. P1: reaffirming a corrected installation could add another original accrual.
   The active-work predicate prevents this; reaffirmation also retains installation
   time instead of moving completed work to the date of the repeated request.
4. P1: project plan/fact actual payroll used the door's initial rate instead of the
   corrected ledger amount. Actual payroll now uses active ledger entries, retaining
   the existing rate fallback only for legacy doors without any ledger history.
   Planned payroll is unchanged; actual profit uses the same corrected payroll.
5. Correction and cancellation now acquire locks in the same order: door, then
   completed work. A correction waiting behind a committed cancellation must return
   a conflict; a cancellation after correction must debit the corrected amount.

No API fields or permissions were removed. No migration is needed: the existing
REVERSAL reference and uniqueness constraints support reversing a CORRECTION.
Rows remain append-only; earnings are accruals, not evidence of bank payments.
